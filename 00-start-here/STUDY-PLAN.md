# Study sequence — prioritize deep understanding before large projects

**Learning route:** targeted architecture foundations first; then data/knowledge and model mechanics; agentic systems; security; operations; full-system design. Timelines are adjustable, mastery is not tied to the calendar.

## Suggested 12-week first cycle
| Weeks | Focus | Primary domains | Evidence |
| --- | --- | --- | --- |
| 1–2 | Failure semantics and safe action | D20, D14, D15 | Unknown-outcome lab + recovery ADR |
| 3–4 | Security and trust boundaries | D16, D17, D18 | Permission-aware retrieval threat model |
| 5–6 | Retrieval, context and evaluation | D05, D06, D07, D24 | Synthetic document benchmark with citations |
| 7–8 | AI models and adaptation | D08–D11 | LoRA matrix worked example + model comparison |
| 9–10 | Agents, tools and integration | D04, D12, D13, D23 | Read-only investigation agent + failure injection |
| 11–12 | Full architecture and ownership | D01–D03, D19, D21–D27 | CTO-ready design defense + release decision |

## Workload
Plan 5 focused sessions weekly; 60–90 minutes per session. Use conceptual study and micro-experiments, not a large implementation backlog. One canonical simulated enterprise project can reuse modules in every pillar.

## Study order is not topic importance
Senior candidates still need breadth across every domain. Specialized mastery is weighted toward agents, RAG, distributed correctness, security, evaluations and ownership. Reevaluate priority against *actual* job descriptions and interview feedback.

## Exit criteria per cycle
- Two unassisted scenario defenses per targeted domain.
- One disconfirming experiment for each major architectural claim.
- At least one security incident exercise and one failure-recovery exercise.
- Updated tracker with failures and follow-up resources.
